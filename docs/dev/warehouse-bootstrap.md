# Native strict-create phases

This source implements the selected strict-create proposal. It was applied to the Snowflake trial account on 2026-10-30 in three phases: CREATE_DISABLED (1 imported, 87 added, 1 changed), IMPORT_DISABLED (3 imported) and READY (4 changed); the apply logs were written between 22:21 and 22:28 UTC. The plan after READY showed no changes (logs in `.tools/terraform/plans/`, not in git). Live grant tests passed 8/8 on 2026-10-31. Native Task1 acceptance remains **OPEN**: no acceptance record closes it. The rest of this document describes the source review and the planned sequence before that apply and has not been updated for it. Neither this document, a phase value, nor the commented [manual SQL](../../warehouse/bootstrap/native-bootstrap.sql) authorizes account access, keys, grants, resource creation or query charges.

The review target is Terraform 1.13.5 with the existing `snowflakedb/snowflake = 2.22.0` pin and existing Terraform version constraint. No backend is provisioned or configured by this change. The original two databases, seven managed schemas, four functional roles and three application service users must be created by a future authorized Terraform apply. Human creation followed by importing those roots would not meet that requirement.

## Implemented configuration

`native_phase` is a case-sensitive enum. Its default remains `NORMAL`. No other resource, service-key input, role assignment or permission matrix is filtered by phase.

| Phase | User `disabled` configuration | Attachment instances | Import declarations | Provider warehouse / warehouse monitor |
|---|---|---|---|---|
| `NORMAL` | `null`, retaining the provider default | Original three | None | Both `null`, preserving prior configuration |
| `CREATE_DISABLED` | String `"true"` for all three | Empty | Original `snowflake_warehouse.compute` only | `SPONSORATLAS_XS` / `SPONSORATLAS_BOOTSTRAP_RM` |
| `IMPORT_DISABLED` | String `"true"` for all three | Original three addresses | Warehouse plus exactly three attachments | Same fixed names |
| `READY` | String `"false"` for all three | Same three addresses | Same import declarations retained | Same fixed names |

The warehouse import ID is `"SPONSORATLAS_XS"`, including identifier quotes. Attachment IDs are `"USER"|"ANALYTICS"."STAGING"."SERVICE_KEY_PAIR_ONLY"`, with `USER` replaced only by `AIRBYTE_SVC`, `DBT_SVC` or `CUBE_SVC`. Their targets remain `snowflake_user_authentication_policy_attachment.service["USER"]`. The import maps use fixed names so their IDs do not depend on computed provider results. The provider warehouse uses a literal local value, not a reference to the warehouse resource, avoiding a provider/resource dependency cycle.

The pinned [warehouse documentation](https://raw.githubusercontent.com/snowflakedb/terraform-provider-snowflake/v2.22.0/docs/resources/warehouse.md) says assigning a resource monitor requires ACCOUNTADMIN; the pinned [warehouse importer](https://raw.githubusercontent.com/snowflakedb/terraform-provider-snowflake/v2.22.0/pkg/resources/warehouse.go) reads the monitor name from SHOW. Assignment must therefore be a separately authorized human action before provider reads, not a deploy-role fallback. After import, `resource_monitor` must be no-op; reject any monitor-change plan without increasing deploy privileges. This is source evidence and inference, not live-account proof.

Application users remain SERVICE with secondary roles `NONE`; their three public-key input entries and LOADER/TRANSFORMER/ANALYST mappings are unchanged. `application_owner_roles` remains empty unless separately authorized. PII_READER receives no identity assignment. This change adds no Terraform resource for an account privilege, deployment identity or resource monitor.

**Intentional lifecycle difference:** attachments now have unconditional `prevent_destroy = true`, including under NORMAL. NORMAL preserves addresses, values and three bindings, not every prior lifecycle behavior. A variable cannot dynamically control this lifecycle setting. It guards destruction while the resource declaration remains present; it neither prevents policy updates using FORCE nor proves that an import refers to an authorized existing binding. Removing the whole resource configuration can also remove lifecycle protection. Independent plan review remains necessary.

## Human monitor/XS fragments — public syntax only

The inert SQL follows documented [monitor](https://docs.snowflake.com/en/sql-reference/sql/create-resource-monitor) and [warehouse](https://docs.snowflake.com/en/sql-reference/sql/create-warehouse) syntax. NEVER does not reset quota; FREQUENCY requires START_TIMESTAMP. The UNRESOLVED END_TIMESTAMP needs a concrete approved UTC literal within <=10 minutes, with confirmed timezone interpretation. No expression/retry/extension; delayed controls are not hard limits.

[SHOW monitors](https://docs.snowflake.com/en/sql-reference/sql/show-resource-monitors) and [SHOW warehouses](https://docs.snowflake.com/en/sql-reference/sql/show-warehouses) need no running warehouse. The SQL specifies exact-name/context/field comparisons, WAREHOUSE-level project-only binding and complete assignment visibility; LIKE wildcards are not equality. Stop on partial/truncated results or collisions. Public syntax proves no live privilege, defaults/generation, import/no-op or effectiveness. The human/key package remains incomplete.

## Cost, abort and recovery limits

Native work has a proposed ten-minute total window, fresh trial expiry/balance evidence and a human-owned project-only one-credit SUSPEND_IMMEDIATE monitor. The monitor must already be assigned before import/reference reads; those reads can resume XS and incur charges. Resource-monitor enforcement is delayed and is not a hard cost ceiling or proof of zero query credits. Preserve XS/single-cluster/auto-suspend60 and current project disk/memory ceilings and floors. No application workloads are started here.

On partial creation or enable failure, the human first inventories what actually exists, disables any of the three created application users, revokes the temporary CREATE grants, suspends XS and verifies suspension, and disables the deployment identity. Do not execute the abort statements against guessed identities. If access or cleanup fails, report the residual state and stop; a timeout does not establish cleanup. On success, revoke the deployment role's user grant and remove the temporary user after no more deployment queries are needed. Revoking CREATE privileges does not revoke ownership of created objects. Ownership return, drops, dependent/future grants and any existing data require explicit reconciliation; neither state rollback, automatic destroy nor credit recovery is a safe default.

The selected state design remains a private Azure Blob backend using Entra authentication through the existing project Azure CLI configuration, `use_cli=true` and `use_azuread_auth=true`, Microsoft-managed SSE and container-scoped access. No SAS/shared key or new SaaS is introduced. Preserve the project CLI configuration; do not reset HOME or copy credentials. This source does not add that backend or configure an account.

**Native execution and key generation remain blocked** until encrypted, access-controlled local workdir, failed `errored.tfstate`, saved plans, cache, crash/temp and recovery handling are proven. Blob SSE and an ext4 mount do not prove encryption of these local artifacts. No host mount, device, FUSE, outside-worktree path or encrypt-after-spill workaround is assumed. Four independent encrypted RSA keys would later be required, with exactly three public keys in the application map and separate offline recovery custody; no key is created or read here.

**State provisioning remains blocked** until a finite TTL, reaper/whole-group deletion contract, independent encrypted export and restore proof prevent destruction of the sole usable state. Suspend/reconcile Snowflake first; prove independent recovery before removing backend/RBAC. No implicit TTL exemption or automatic extension is approved. Later Azure creation requires a Retail Prices API ledger estimate including retention/versions/operations/egress, cumulative estimate <= $5.40 of $6, `rg-sponsoratlas-lab` only and the four required project/owner/ttl/est_usd_per_hour tags. Never touch `rg-mlinfra-westus`.
