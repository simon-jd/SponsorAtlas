## RUM semantics, privacy and storage

Pinned `web-vitals`6.2.3 uses `onLCP`, `onINP`, `onCLS` once per document. The non-attribution build emits only metric name/id/value/sequence plus random document navigation identity, route class (search/employer/compare/map), locale, viewport class (narrow<768/wide), and document/BFcache type. It does not transmit full URLs, query strings, employer IDs, DOM entries, user IDs, IPs, request headers, credentials, source rows or coordinates. DNT/GPC suppress collection. SPA route transitions never relabel a previous document's metrics; soft-navigation collection is explicitly disabled. BFcache restores create a new application epoch even when the browser reports navigationId0 again. No observer is registered on each route change.

Metric updates replace the same navigation/name only when the stable metric ID matches and sequence increases. Reordered retries cannot overwrite a newer value. A missing INP callback is **unobserved**, not0. LCP can also be absent on background-first documents. Observed CLS0 is legitimate. Document metrics can include later client-side interactions and are explicitly grouped as document observations; this does not claim independent SPA page views. `reportAllChanges:false` follows final/visibility-change callbacks; sendBeacon fallback uses bounded keepalive requests. Browser closing, privacy suppression and request/storage rejection can cause missing samples; field representativeness cannot be assumed.

`POST /api/vitals` requires exact configured canonical `RUM_ORIGIN` (HTTPS production; explicit loopback QA) and same-origin JSON and a streaming2048-byte limit; exact scalar allowlists reject extra fields, duplicates, nonfinite/out-of-range values and invalid IDs. Its early per-process rate is90/minute, persisted adapter rate60/minute, queue8, retention7days, hardcap6000 rows/2MB. Recent samples are never silently evicted to pass quota; overflow returns429. Storage failures/missing configuration return503. Local QA requires both `RUM_STORAGE=local` and `RUM_QA_ONLY=1` plus an explicit directory. It is an intentionally ephemeral, serialized one-process sink.

The concrete production adapter reads/writes exactly one private Azure Block Blob using HTTPS, bounded streaming reads, four-second timeouts, ETag `If-Match` / initial `If-None-Match:*`, and at most three conflict retries. It needs a finite-expiry blob-scoped read/create/write SAS held server-side, and a precreated private container. It has **no production local fallback**. The prepared ARM lifecycle removes inactive blobs after seven days; active writes prune expired rows. Versioning/soft-delete are disabled in the prepared storage contract to avoid hidden unbounded histories. Controlled transport tests validate CAS/retry semantics, not an observed Azure Blob service. Public launch still requires abuse/cost and real durable-restart validation.
